# Управляемые синтетические фикстуры Stage 12

## Назначение и публичная граница

Версия фикстуры `stage12-v1` задаёт полностью синтетические объекты для будущих 50 заданий только для чтения: по десять для Gmail, Calendar, Drive, Sheets и Docs. Публичный каталог содержит только логические ссылки, непрозрачные маркеры, синтетические значения и форму будущих запросов. В нём нет Google ID, адреса аккаунта, пользовательского содержимого, токенов и значений ссылок на учётные данные.

XML-файлы заданий появятся после живого посева и однократной проверки готовности. До состояния `ready` функция `require_ready_for_xml()` запрещает их авторство.

## Приватный `bindings.json`

Будущий гейт записи создаёт `private/evals/bindings.json` с режимом `0600`. Чтение отклоняет симлинки, специальные файлы, чужого владельца, другой режим, неизвестные поля и несовместимую версию. Поля `owner_email` и `calendar_primary_id` являются приватными значениями и маскируются Pydantic при сериализации. Поля `credentials.*.reference` содержат только ссылки на отдельные файлы пользовательского OAuth2 и никогда не содержат токены или секреты клиента.

```json
{
  "fixture_version": "stage12-v1",
  "state": "planned",
  "owner_email": "<private-owner-address>",
  "calendar_primary_id": "<private-calendar-id>",
  "credentials": {
    "gmail": {"service": "gmail", "kind": "oauth_user", "reference": "oauth/gmail.json"},
    "calendar": {"service": "calendar", "kind": "oauth_user", "reference": "oauth/calendar.json"},
    "drive": {"service": "drive", "kind": "oauth_user", "reference": "oauth/drive.json"},
    "sheets": {"service": "sheets", "kind": "oauth_user", "reference": "oauth/sheets.json"},
    "docs": {"service": "docs", "kind": "oauth_user", "reference": "oauth/docs.json"}
  },
  "objects": {},
  "applied_operations": []
}
```

`planned` означает, что посев ещё не завершён. После каждого успешного будущего запроса гейт атомарно добавляет его имя в `applied_operations` и записывает полученные идентификаторы в `objects`. `applied` означает, что все 14 операций записи зарегистрированы, но готовность ещё не подтверждена. `ready` разрешается только после полного прохода чтения всех логических ссылок.

Если реестр содержит часть объектов или операций, повторное применение запрещено. Новый превью показывает все оставшиеся операции, помечает частично связанный составной результат как `blocked_partial_output` и требует ручного разбора реестра. Поиск по всему аккаунту для угадывания состояния не выполняется. Очистка и удаление фикстур в Stage 12 не входят.

## Полный превью записи

Команда строит настоящие объекты запросов `google-api-python-client`, читает их `method`, `uri` и `body`, но не вызывает `.execute()`:

```bash
cd app
uv run --no-sync python -m google_workspace_mcp.evals preview
```

Для проверки остатка по существующему приватному реестру используется `--bindings`:

```bash
uv run --no-sync python -m google_workspace_mcp.evals preview --bindings ../private/evals/bindings.json
```

Превью включает 14 операций: четыре Gmail, три Calendar, три Drive, две Sheets и две Docs. Адрес владельца в Gmail заменён ссылкой `bindings.owner_email`, идентификатор основного календаря заменён ссылкой `bindings.calendar_primary_id`, а зависимости между запросами представлены логическими ссылками.

Применение не является подкомандой этого модуля и в Task 1 не реализовано. Функция `confirm_application()` проверяет отдельный объект `ApplicationConfirmation`, точную версию и SHA-256 показанного превью, после чего возвращает только неизменяемый план запросов без выполнения. Будущий исполнитель записи обязан отдельно получить пользовательские OAuth2 credentials для каждой службы, подставить приватные значения и только затем исполнить подтверждённый план. Сервисный аккаунт для посева запрещён, потому что личный Google-аккаунт не даёт ему квоту владения файлами.

Процесс полного прогона заданий не принимает и не получает токены с полным доступом. После посева он использует пять отдельных клиентских токенов `mcp_readonly_v1` и точные реестры инструментов 7/5/3/3/2. Значения токенов не входят в XML, `bindings.json`, аргументы командной строки, вывод или доказательства.

## Контракты служб

Gmail разделяет draft ID, message ID, thread ID и подтверждение доставки. Две цепочки имеют разное число сообщений, а каждое отправление имеет отдельный непрозрачный маркер. Проверка доставки выполняет один ограниченный поиск с `max_results=1` по точному маркеру. Отсутствие результата даёт `not_ready`, автоматического повтора нет. Пользовательские метки, темы, адресаты, фрагменты и тела не читаются; будущие задания по меткам используют только системные метки с сортировкой по `label_id`.

Calendar использует только основной календарь через приватную ссылку и фиксированное окно с 2027-02-01 по 2027-03-01. Все события имеют точный маркер, `sendUpdates=none` и не содержат участников. Имена пользовательских календарей и чужая занятость не входят в фикстуру.

Drive создаёт одну выделенную папку и два объекта внутри неё, каждый с уникальным маркером. Sheets создаёт одну таблицу с двумя листами и только теми значениями и формулами, которые нужны будущим десяти заданиям. Docs создаёт один документ и одну вкладку с ограниченным синтетическим текстом.

## Проверка готовности

`check_readiness()` принимает только `applied` или `ready` bindings и внедряемый клиент чтения. Для трёх Gmail deliveries выполняется ровно по одному поиску точного маркера, для остальных логических ссылок ровно по одному чтению привязанного объекта. Отсутствующая связь не вызывает широкого поиска и возвращает `not_ready`. Только полный отчёт, содержащий все логические ссылки и точное число проб, может перевести реестр в `ready` через `mark_bindings_ready()`.
